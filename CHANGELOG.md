# Changelog

Versions of this documentation suite are tagged against the [symfony/ai](https://github.com/symfony/ai) monorepo: `major.minor` is the symfony/ai line the skills target, and the patch number counts releases of the skills within that line (so `0.14.2` is the second release for symfony/ai 0.14, not a symfony/ai 0.14.2). See README § Maintenance for the refresh policy.

## [0.14.2] - 2026-10-04

Skills for `symfony/ai` 0.14, still verified against 0.14.1 (no upstream release since). Breaking for users: one skill removed and every other skill renamed; a manual install needs the cleanup described in `INSTALL.md`.

- **Removed the `symfony-ai` orchestrator skill.** The host agent already routes on every skill's `name` and `description`; the orchestrator added a load hop, its broad description ("how do I add AI to my Symfony app", "combine RAG with a chat session") competed with `store` and `chat`, and its copy of the routing table had drifted (it still called Mate an MCP dev server). Its three anti-patterns moved to the skills they belong to: vendor SDKs such as `openai-php/client` (`platform`), embeddings in a MySQL `JSON` column (`store`), hand-rolled session-file chat state (`chat`). CI no longer special-cases it; `AGENTS.md`, `GEMINI.md`, `README.md` and `llms.txt` drop it.
- `mcp-bundle` : the bundle requires `mcp/sdk ^0.8.1`, not `^0.7`.
- `mate` : dropped the stale `App::VERSION` = `'0.13.0'` claims (0.14.1 ships `'0.14.0'`); `llms.txt` no longer calls Mate an MCP dev server.
- **Skills renamed after their Composer packages** (breaking): `platform` → `symfony-ai-platform`, `agent` → `symfony-ai-agent`, `chat` → `symfony-ai-chat`, `store` → `symfony-ai-store`, `ai-bundle` → `symfony-ai-bundle`, `mcp-bundle` → `symfony-mcp-bundle`, `mate` → `symfony-ai-mate`. The generic names collided with other skills in flat skill directories; `INSTALL.md` explains how to remove the old copies of a manual install.
- **`references/api.md` renamed to `references/api-reference.md`** in six skills; the reference-name whitelist (both CI files, README) follows.
- **Descriptions rewritten for routing**: 424–495 characters instead of 625–846, user intent first, third person (no "my"/"your" inside quoted questions), a few discriminating symbols, and a `Not for … (sibling skill)` clause. Measured with `claude -p` on the 28 eval prompts (3 runs each, only these skills loaded): 83/84 correct routings before; the first rewrite fell to 72/84 because four prompts that never name Symfony or PHP (multi-agent routing, tools + memory, chatbot history, RAG chunking) stopped triggering, which an explicit "even when the question does not name Symfony" clause in `symfony-ai-agent`, `symfony-ai-chat` and `symfony-ai-store` fixed: 48/48 on the 16 prompts that clause could affect, and the other 12 had already passed 36/36 with unchanged descriptions.
- **Every `SKILL.md` restructured on one template**: Purpose, When to use, When not to use (naming the sibling skill), Prerequisites, Examples, Key gotchas, Troubleshooting (exact error messages from the 0.14.1 source → cause → fix), Limitations, Usage, conditional References. `metadata.tags` added (a string, as the spec requires). `symfony-mcp-bundle/SKILL.md` drops from ~4,200 to ~2,600 tokens: compiler-pass internals and the full client configuration now live only in its references. `symfony-ai-mate` and `symfony-mcp-bundle` list their key gotchas as bullets instead of one run-on sentence.
- **Fixes found by checking every cited symbol and message against the 0.14.1 source**: `Model "…" does not support "tool calling"` is never thrown (only structured output is enforced); there is no `ModelRouter` class (`ModelRouterInterface`); the mcp-bundle class-level-attribute error prints the attribute's full class name; the 43 platform bridges include the `Failover` and `Cache` decorators; STDIO sessions are not stored outside the session store (claim removed); message stores do not serialise concurrent writers (a moved claim said they did); `StoreInterface::query()` yields `VectorDocumentInterface`; `ToolProcessor` no longer exists (ai-bundle `processors.md`); Mate's `FilteredDiscoveryLoader::isFeatureAllowed()`, `CapabilityCollector::formatTools()` and `ExtensionConfigSynchronizer::writeExtensionsFile()` do not exist (now `CapabilityRegistry::isFeatureAllowed()`, `ReflectionDiscoverer`, `Skill\SkillStateRepository::write()`).
- References: no more links between reference files or across skills (the agent → chat link would break when a skill is installed alone); `store/references/bridges.md` puts its Contents list before the 24-row table; section names replace broken `#anchor` links.
- Evals: renamed skills; `agent-002` no longer expects `MemoryInputProcessor` to hold conversation history (the skill says memory is read-only; history is `symfony-ai-chat`); `ai-bundle-002` no longer accepts `#[AsTool]` on a method.

## [0.14.1] - 2026-09-28

Tracks `symfony/ai`'s 0.14.1 release (UPGRADE 0.13 → 0.14; 0.14.1 itself only ships bug fixes).

- `store` : `StoreInterface` extends `\Countable` (`count(): int`); stores, retrievers, rerankers, vectorizers and `DistanceCalculator` are typed against the new `Document\VectorDocumentInterface`; `VectorQuery`/`HybridQuery` take and return `VectorInterface`. Elasticsearch, ManticoreSearch, Milvus, Neo4j, OpenSearch and Supabase stores take a scoped HTTP client, with endpoint/credentials moved to each bridge's new `StoreFactory` : documented the seven new factories (ClickHouse included), their signatures, and the silent positional-argument shift when upgrading. `SourceIndexer` now forwards its options to the loader. New gotchas: scoped-client migration, and Elasticsearch/OpenSearch `_bulk` partial failures now throwing (0.14.1).
- `platform` : `TokenUsageInterface::getModel()` (and `TokenUsageAggregation`'s `null`-on-disagreement rule); `convertStreamUsage()`'s new `?string $model` argument. New `Job\` subsystem (`JobHandle`, `JobRunner`, `JobClientInterface`, `JobStatus`, `JobStateCase`, `JobResult`, `DeferredResult::asJob()`): Replicate and MiniMax (async) no longer wait and return a job. Documented batches (`BatchResult`, `BatchItem`, `asBatch()`), `RealtimeSessionResult`/`Capability::REALTIME_SESSION`, Anthropic `server_tools` + `WebSearchResult`, `TraceablePlatform`'s optional `Stopwatch`. Six new bridges (Eden AI, Fireworks, Higgsfield, Together, TypeSafe, Venice) : catalogue goes from 37 to 43.
- `agent` : `ToolCallArgumentResolver` throws `InvalidToolCallArgumentsException` (was `ToolException`); `SimilaritySearch::getUsedDocuments()` returns `VectorDocumentInterface[]`. Documented `Execution::cancel()`/`isStreamed()`, `FiberToolExecutor` + `SuspendableTrait`, `AbstractToolbox`, `ChainToolbox`, `#[MapToolArguments]`, `Stopwatch` on `TraceableToolbox`/`TraceableAgent`, `MultiAgent`/`SpeechAgent` progress forwarding (`handoff` stage), and the new `Mcp\McpToolbox` tool bridge (`symfony/ai-mcp-tool`).
- `ai-bundle` : replaced every source line-number reference (`AiBundle.php`, `options.php`, `services.php`, compiler passes, security listener; several were already off in 0.13.0) with stable anchors : method names, service ids, config node paths. Removed a leftover claim about a `ToolProcessor` tagged as input and output processor (gone since 0.13). Six new platform keys, Bedrock `api` option (InvokeModel vs Mantle routes), `ai.platform.job_runner` and `ai.platform.job_client.<name>` services, `tools.execution_strategy` (`sequential`/`fiber`/service id), `mcp_server` tool entries (+ `prefix`), `http_client` as an alternative to the endpoint on the seven scoped-client stores, profiler performance timeline.
- `mcp-bundle` : cross-link to `ai-bundle`'s `mcp_server` tool entry from the client pattern.
- `mate` : `tools:list` `Arguments` column, `tools:call` 8 KB pretty→JSON fallback and `tools:inspect` hint, `skills:install` per-skill `action` table and `--format`.
- `platform`, `store`, `chat`, `mcp-bundle` : same treatment for the remaining `File.php:NN`-style references (`FailoverPlatform::do()`, `RssFeedLoader::load()`, `MongoDb\MessageStore::save()`, …). No skill cites a source line number anymore; the convention is recorded in `README.md` § Maintenance and `CLAUDE.md`. `llms.txt` platform bridge count updated (37 → 43).
- Every skill's `version:` frontmatter and the plugin/extension manifests bumped from `0.13.0` to `0.14.1`.

## [0.13.0] - 2026-09-01

Tracks `symfony/ai`'s 0.13.0 release.

- `agent` : `AgentProcessor` removed — `Agent` drives tool calling itself via `toolbox`/`maxToolCalls`/`includeSources`/`toolExecutor` constructor arguments, with `SequentialToolExecutor` as the default `ToolExecutorInterface`. `AgentInterface::call()` returns a lazy `Execution` instead of `ResultInterface` : documented its eager/observable/explicit-resolve usage, its laziness consequences (side effects deferred to `getContent()`/`getResult()`/iteration, `instanceof` needs `getResult()` first, input processors run once per call not per tool round), and a streaming pattern; removed the stale `Toolbox\StreamListener` section and the gotcha claiming `Agent` still attaches one internally; fixed 6 stale `ResultInterface` return types in `api.md`. Documented per-call tool filtering (`Agent::call($input, ['tools' => [...]])`); named the internal `Execution\Runner` class and removed a previously-cited `Execution\ToolCallBudget` class that does not exist. Fixed an orphaned gotcha paragraph. Fixed three wrong namespaces in `api.md` : `ReflectionToolFactory`/`MemoryToolFactory`/`ChainFactory` moved from `Toolbox\` to `Toolbox\ToolFactory\`; `Execution` moved from `Agent\` to `Agent\Execution\`; `Decision` moved from `MultiAgent\` to `MultiAgent\Handoff\`. Fixed `MockAgent::assertCallCount()`'s parameter name (`$expected` → `$expectedCount`). Fixed `ToolExecutorInterface`/`SequentialToolExecutor::execute()`'s return type (`array` → `\Generator<int, UpdateInterface, mixed, ToolResult[]>`). Added the missing `Template` type to `SystemPromptInputProcessor`'s `$systemPrompt` union.
- `ai-bundle` : `keep_tool_messages` renamed to `exclude_tool_messages` (same value semantics). Documented the `postgres` store schema — the exact backend the official `demo/` app runs. Removed the "legacy" label on the bare-list `tools:` form — it's what `demo/` actually uses everywhere.
- `chat` : `ChatStreamListener` removed — `Chat::stream()` now consumes the agent's `Execution` itself (yields deltas, persists the assistant turn with result metadata once the stream ends). Removed the stale listener documentation from `api.md`, `SKILL.md`, `gotchas.md`, and `patterns.md`. Documented that a persisted assistant turn can now carry a structured `Thinking` part instead of only text. Fixed a swapped argument order in a `DoctrineDbalMessageStore` example; added the "streaming + Session store" warning from the official docs.
- `mcp-bundle` : multi-server support — every option moves under `mcp.servers.<name>`, capabilities are opt-in via a required `registry` key, per-server services replace the old singletons, route name is `_mcp_endpoint_<name>`, default HTTP path `/mcp/<name>`, `mcp:server`/`debug:mcp` gain a server argument/option. New: the bundle can act as an MCP client (`mcp.clients.<name>`) reaching remote servers. Every HTTP server now also serves the 2026-07-28 protocol revision alongside the handshake era, which removes server-initiated requests — a handler calling `$gateway->sample()`/`listRoots()` now breaks for modern clients on the same endpoint it worked on before. Documented the break, the `supportsSampling()`/`supportsRoots()` guard, `servers.<name>.protocol_versions` to pin to the handshake era, and `servers.<name>.request_state.key` (required for a handler that elicits more than once, without a session). Fixed two stale service ids left over from the multi-server rewrite (`mcp.server.debug_command` → `mcp.debug_command`, `mcp.app.reference_handler` → per-server) and documented an HTTP-path uniqueness constraint. Documented a silent regression : `servers.<name>.subscriptions.bus` defaults to `none`, which never wires up delivery for `resources/subscribe` and list-changed notifications — a client on the 2026-07-28 revision (the default for every client, see above) stops receiving subscription notifications after upgrading to 0.13 with no error, until `bus` is set to `memory` or `cache`.
- `mate` : skills are copied into `.agents/skills/mate-<name>/` (safe to commit) instead of symlinked into `vendor/`; `.claude/skills/` mirrors via a relative symlink. `mate/extensions.php` splits editable (`enabled`, `mode`) from tool-written (`state`, `source`, `source_hash`, `hash`, `targets`) fields. Mate no longer runs an MCP server : rewrote `SKILL.md` and all 3 references, which still described `mate serve`/`stop`, generated `mcp.json`/`.mcp.json`, `mcp:tools:*` commands, and an "Editor MCP configuration" section, to reflect command renames (`tools:list`, `tools:call --limit=1`, …), native `Symfony\AI\Mate\Attribute\{MateTool,MateResource,MateResourceTemplate}` replacing the `mcp/sdk` attributes (`name` now required, method-only placement), removal of Prompts, the `untrusted_data` response envelope, `monolog-tail --limit`, unknown-`--format` rejection, and the new `mate.invocation`/`mate.php_version` config parameters. Removed two nonexistent DI-parameter claims (`mate.skills_dir`/`mate.skill_mirrors` — the install paths are hardcoded constants). Documented 7 CLI commands added since 0.12.0 (`skills:list`, `skills:validate`, `skills:prune`, `skills:override`, `skills:reset`, `skills:disable`, `skills:enable`); fixed a nonexistent method-name citation and a stale line reference.
- `platform` : `Result\Stream\ListenerInterface` gains `onError(ErrorEvent)`; Gemini/VertexAI bridges batch `ToolCallComplete` at stream end instead of one per function call (multi-candidate responses excepted). Documented `FailoverPlatform`'s optional `$clock`/`$logger` constructor args.
- Every skill's `version:` frontmatter bumped from `0.13.0-dev` to `0.13.0`.

Known gap: `mcp-bundle`'s `cache` server option (present in `src/mcp-bundle/config/options.php`, absent from UPGRADE.md) is undocumented — its `ttl_ms` defaults to `0` (no caching), so it is cosmetic and opt-in with no default-behavior impact. `subscriptions` is no longer a gap : see the `mcp-bundle` entry above and gotcha 16.

Also fixed : `skills/symfony-ai/SKILL.md`'s body text still said "Last verified against `symfony/ai` v0.12.0" after the frontmatter `version:` had already been bumped to `0.13.0`.

**New tool, `scripts/check-method-signatures.sh`**: `check-symbols.sh` only proves a cited `Symfony\AI\*` class resolves to a file; it says nothing about whether the methods and parameters documented on that class are still accurate. The new script parses every `namespace X; class Y { ... }` signature block in `skills/**/*.md` (the format `references/api.md` files already use throughout) and diffs each documented method against the real source — parameter count and names hard-fail on mismatch, types/defaults/return-types warn. Not wired into CI yet; run manually after touching an `api.md`.

**New tool, `scripts/reflect-signatures.php`**: gives `check-method-signatures.sh` real PHP Reflection instead of text parsing, for any component `composer install`ed inside its own `src/<component>/` (all 7 now installed locally). Reflection resolves inherited methods and fully-qualifies every type, which cut the script's WARN count from 33 to 5 on the current docs by eliminating false mismatches between a short doc-side type name and its fully-qualified reflected form, `self`/`static` vs the literal class name, and this script's own `new X(...)` default-value rendering. A component without an installed `vendor/autoload.php` still falls back to the text parser.

## [0.12.0] - 2026-08-27

Initial release: 8 agent skills (Platform, Agent, Chat, Store, AI Bundle, MCP Bundle, Mate, Symfony AI orchestrator).

**Corrected same-day**: `agent`, `ai-bundle`, and `chat` initially documented `symfony/ai`'s post-0.13 API (`Agent` with a `toolbox`/`maxToolCalls`/`includeSources` constructor, `exclude_tool_messages`) instead of the real v0.12.0 API (`AgentProcessor` wired as both an input and an output processor, `keep_tool_messages`). The `v0.12.0` tag was moved to the corrected commit before any consumer depended on it.
