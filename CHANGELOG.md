# Changelog

Versions of this documentation suite are tagged against the [symfony/ai](https://github.com/symfony/ai) monorepo. See README § Maintenance for the refresh policy.

## [0.13.0] - 2026-09-01

Tracks `symfony/ai`'s 0.13.0 release.

- `agent` : `AgentProcessor` removed — `Agent` drives tool calling itself via `toolbox`/`maxToolCalls`/`includeSources`/`toolExecutor` constructor arguments, with `SequentialToolExecutor` as the default `ToolExecutorInterface`. `AgentInterface::call()` returns a lazy `Execution` instead of `ResultInterface` : documented its eager/observable/explicit-resolve usage, its laziness consequences (side effects deferred to `getContent()`/`getResult()`/iteration, `instanceof` needs `getResult()` first, input processors run once per call not per tool round), and a streaming pattern; removed the stale `Toolbox\StreamListener` section and the gotcha claiming `Agent` still attaches one internally; fixed 6 stale `ResultInterface` return types in `api.md`. Documented per-call tool filtering (`Agent::call($input, ['tools' => [...]])`); named the internal `Execution\Runner` class and removed a previously-cited `Execution\ToolCallBudget` class that does not exist. Fixed an orphaned gotcha paragraph. Fixed three wrong namespaces in `api.md` : `ReflectionToolFactory`/`MemoryToolFactory`/`ChainFactory` moved from `Toolbox\` to `Toolbox\ToolFactory\`; `Execution` moved from `Agent\` to `Agent\Execution\`; `Decision` moved from `MultiAgent\` to `MultiAgent\Handoff\`. Fixed `MockAgent::assertCallCount()`'s parameter name (`$expected` → `$expectedCount`). Fixed `ToolExecutorInterface`/`SequentialToolExecutor::execute()`'s return type (`array` → `\Generator<int, UpdateInterface, mixed, ToolResult[]>`). Added the missing `Template` type to `SystemPromptInputProcessor`'s `$systemPrompt` union.
- `ai-bundle` : `keep_tool_messages` renamed to `exclude_tool_messages` (same value semantics). Documented the `postgres` store schema — the exact backend the official `demo/` app runs. Removed the "legacy" label on the bare-list `tools:` form — it's what `demo/` actually uses everywhere.
- `chat` : `ChatStreamListener` removed — `Chat::stream()` now consumes the agent's `Execution` itself (yields deltas, persists the assistant turn with result metadata once the stream ends). Removed the stale listener documentation from `api.md`, `SKILL.md`, `gotchas.md`, and `patterns.md`. Documented that a persisted assistant turn can now carry a structured `Thinking` part instead of only text. Fixed a swapped argument order in a `DoctrineDbalMessageStore` example; added the "streaming + Session store" warning from the official docs.
- `mcp-bundle` : multi-server support — every option moves under `mcp.servers.<name>`, capabilities are opt-in via a required `registry` key, per-server services replace the old singletons, route name is `_mcp_endpoint_<name>`, default HTTP path `/mcp/<name>`, `mcp:server`/`debug:mcp` gain a server argument/option. New: the bundle can act as an MCP client (`mcp.clients.<name>`) reaching remote servers. Every HTTP server now also serves the 2026-07-28 protocol revision alongside the handshake era, which removes server-initiated requests — a handler calling `$gateway->sample()`/`listRoots()` now breaks for modern clients on the same endpoint it worked on before. Documented the break, the `supportsSampling()`/`supportsRoots()` guard, `servers.<name>.protocol_versions` to pin to the handshake era, and `servers.<name>.request_state.key` (required for a handler that elicits more than once, without a session). Fixed two stale service ids left over from the multi-server rewrite (`mcp.server.debug_command` → `mcp.debug_command`, `mcp.app.reference_handler` → per-server) and documented an HTTP-path uniqueness constraint. Documented a silent regression : `servers.<name>.subscriptions.bus` defaults to `none`, which never wires up delivery for `resources/subscribe` and list-changed notifications — a client on the 2026-07-28 revision (the default for every client, see above) stops receiving subscription notifications after upgrading to 0.13 with no error, until `bus` is set to `memory` or `cache`.
- `mate` : skills are copied into `.agents/skills/mate-<name>/` (safe to commit) instead of symlinked into `vendor/`; `.claude/skills/` mirrors via a relative symlink. `mate/extensions.php` splits editable (`enabled`, `mode`) from tool-written (`state`, `source`, `source_hash`, `hash`, `targets`) fields. Mate no longer runs an MCP server : rewrote `SKILL.md` and all 3 references, which still described `mate serve`/`stop`, generated `mcp.json`/`.mcp.json`, `mcp:tools:*` commands, and an "Editor MCP configuration" section, to reflect command renames (`tools:list`, `tools:call --limit=1`, …), native `Symfony\AI\Mate\Attribute\{MateTool,MateResource,MateResourceTemplate}` replacing the `mcp/sdk` attributes (`name` now required, method-only placement), removal of Prompts, the `untrusted_data` response envelope, `monolog-tail --limit`, unknown-`--format` rejection, and the new `mate.invocation`/`mate.php_version` config parameters. Removed two nonexistent DI-parameter claims (`mate.skills_dir`/`mate.skill_mirrors` — the install paths are hardcoded constants). Documented 7 CLI commands added since 0.12.0 (`skills:list`, `skills:validate`, `skills:prune`, `skills:override`, `skills:reset`, `skills:disable`, `skills:enable`); fixed a nonexistent method-name citation and a stale line reference.
- `platform` : `Result\Stream\ListenerInterface` gains `onError(ErrorEvent)`; Gemini/VertexAI bridges batch `ToolCallComplete` at stream end instead of one per function call (multi-candidate responses excepted). Documented `FailoverPlatform`'s optional `$clock`/`$logger` constructor args.
- Every skill's `version:` frontmatter bumped from `0.13.0-dev` to `0.13.0`.

Known gap: `mcp-bundle`'s `cache` server option (present in `src/mcp-bundle/config/options.php`, absent from UPGRADE.md) is undocumented — its `ttl_ms` defaults to `0` (no caching), so it is cosmetic and opt-in with no default-behavior impact. `subscriptions` is no longer a gap : see the `mcp-bundle` entry above and gotcha 16.

Also fixed : `skills/symfony-ai/SKILL.md`'s body text still said "Last verified against `symfony/ai` v0.12.0" after the frontmatter `version:` had already been bumped to `0.13.0`.

**New tool, `scripts/check-method-signatures.sh`**: `check-symbols.sh` only proves a cited `Symfony\AI\*` class resolves to a file; it says nothing about whether the methods and parameters documented on that class are still accurate. The new script parses every `namespace X; class Y { ... }` signature block in `skills/**/*.md` (the format `references/api.md` files already use throughout) and diffs each documented method against the real source — parameter count and names hard-fail on mismatch, types/defaults/return-types warn. Not wired into CI yet; run manually after touching an `api.md`.

**New tool, `scripts/reflect-signatures.php`**: gives `check-method-signatures.sh` real PHP Reflection instead of text parsing, for any component `composer install`ed inside its own `src/<component>/` (all 7 now installed locally). Reflection resolves inherited methods and fully-qualifies every type, which cut the script's WARN count from 33 to 5 on the current docs by eliminating false mismatches between a short doc-side type name and its fully-qualified reflected form, `self`/`static` vs the literal class name, and this script's own `new X(...)` default-value rendering. A component without an installed `vendor/autoload.php` still falls back to the text parser.

## [0.12.0] - 2026-08-27

Initial release: 8 agent skills (Platform, Agent, Chat, Store, AI Bundle, MCP Bundle, Mate, Symfony AI orchestrator).

**Corrected same-day**: `agent`, `ai-bundle`, and `chat` initially documented `symfony/ai`'s post-0.13 API (`Agent` with a `toolbox`/`maxToolCalls`/`includeSources` constructor, `exclude_tool_messages`) instead of the real v0.12.0 API (`AgentProcessor` wired as both an input and an output processor, `keep_tool_messages`). The `v0.12.0` tag was moved to the corrected commit before any consumer depended on it.
